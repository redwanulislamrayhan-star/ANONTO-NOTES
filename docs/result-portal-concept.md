# সার্ভার থেকে তথ্য এনে নিজের সাইটে দেখানোর কনসেপ্ট
### (রোল/রেজিস্ট্রেশন নম্বর দিলে সরকারি সার্ভার থেকে রেজাল্ট নিজের সাইটে শো করার সিস্টেম)

> তারিখ: ১৯ আগস্ট ২০২৬ ・ ভাষা: বাংলা ・ উদ্দেশ্য: ধারণা বোঝানো (কোড নয়)

## ১. সংক্ষেপে উত্তর

**হ্যাঁ, আপনার বর্ণিত সিস্টেম সম্ভব এবং বাংলাদেশে অনেক সাইট আগে থেকেই ঠিক এভাবেই চলে।** যেমন:

- `webresult.bd`, `bdadmissions.com`, `sscresult.bd` — এরা সরকারি সার্ভার থেকে রেজাল্ট এনে নিজের সাইটে দেখায়
- GitHub-এ `AKASH-UWU/EDUBOARDBD` — ওপেন-সোর্স রেজাল্ট স্ক্র্যাপার, যা `educationboardresults.gov.bd` থেকে অটোমেটিক রেজাল্ট আনে (এমনকি ক্যাপচাও অটো-সলভ করে)

আপনার সাইটে নিজের কোনো ডাটা থাকবে না — শুধু **মাঝখানে "প্রক্সি"** হিসেবে কাজ করবে: ব্যবহারকারীর ইনপুট নিয়ে সরকারি সার্ভারে ফরওয়ার্ড করবে, উত্তরটা পার্স করে নিজের সাইটে সুন্দর করে দেখাবে।

## ২. এই প্যাটার্নটার নাম কী

এটাকে বলা হয় **"Data Proxy / Result Scraper / Result Portal"**। মূল নীতি:

- ✅ আপনার সাইটে কোনো রেজাল্ট **জমা থাকে না**
- ✅ মানুষ সার্চ করলে **সেই মুহূর্তে** উৎস সার্ভার থেকে আনা হয়
- ✅ উৎস সার্ভার না বদলালে আপনার সাইটও বদলায় না — শুধু দেখার চেহারা বদলায়

## ৩. কীভাবে কাজ করবে (ধাপে ধাপে)

```
শিক্ষার্থীর ব্রাউজার
        │
        ▼
আপনার সাইট (ফ্রন্টএন্ড — ফর্ম: বোর্ড, পরীক্ষা, বছর, রোল, রেজি, ক্যাপচা)
        │
        │  POST (রোল + রেজিস্ট্রেশন + ...)
        ▼
আপনার ব্যাকএন্ড সার্ভার (Node.js / Python / PHP)
        │
        │  HTTP POST — ঠিক ব্রাউজারের মতো (ফর্ম ডাটা + সেশন কুকি)
        ▼
সরকারি সার্ভার  educationboardresults.gov.bd
        │
        │  HTML রেজাল্ট পেজ ফেরত
        ▼
আপনার ব্যাকএন্ড (HTML পার্স করে → পরিষ্কার JSON বানায়)
        │
        │  JSON
        ▼
আপনার সাইটে সুন্দর মার্কশিট/জিপিএ শো — সাইট ছেড়ে যাওয়ার দরকার নেই
```

**প্রতিটি রিকোয়েস্টের ভেতরে যা ঘটে:**

1. শিক্ষার্থী আপনার সাইটে বোর্ড (যেমন: ঢাকা), পরীক্ষা (SSC), বছর (২০২৬), রোল ও রেজিস্ট্রেশন নম্বর দেয়
2. আপনার ব্যাকএন্ড সেই ডাটা দিয়ে সরকারি সার্ভারে রিকোয়েস্ট পাঠায় — ব্রাউজার যেভাবে ফর্ম সাবমিট করে, ঠিক সেভাবে
3. সরকারি সার্ভার রেজাল্টের HTML পেজ ফেরত দেয়
4. আপনার ব্যাকএন্ড সেই HTML থেকে নাম, জিপিএ, সাবজেক্ট গ্রেড, পাস/ফেল ইত্যাদি বের করে JSON বানায়
5. আপনার ফ্রন্টএন্ড সেটা দেখায়

## ৪. কেন নিজের ব্যাকএন্ড সার্ভার লাগবে (আপনি বলেছিলেন "আপনিই ঠিক করুন" — তাই ঠিক করে দিলাম)

**ব্যাকএন্ড সার্ভার ছাড়া এই কাজটা করা যায় না।** তিনটা কারণ:

1. **CORS নিয়ম**: ব্রাউজার কোনো ওয়েবসাইটকে অন্য ডোমেইনের (gov.bd) সার্ভারে সরাসরি রিকোয়েস্ট পাঠাতে বাধা দেয়। তাই মাঝখানে আপনার সার্ভার দরকার — সার্ভার-থেকে-সার্ভার রিকোয়েস্টে এই বাধা নেই।
2. **ক্যাপচা + সেশন কুকি**: সরকারি সাইট ক্যাপচা যাচাই করার জন্য একটা সেশন/কুকি ধরে রাখে। ব্যাকএন্ড সেই কুকি ম্যানেজ করতে পারে; ব্রাউজার পারে না।
3. **ক্যাশ ও রেট-লিমিট**: সরকারি সার্ভারে চাপ কমানোর জন্য ক্যাশিং করতে হয় — সেটা শুধু ব্যাকএন্ডেই সম্ভব।

## ৫. সবচেয়ে বড় চ্যালেঞ্জ: CAPTCHA

সরকারি রেজাল্ট সাইটে **ক্যাপচা** আছে (টেক্সট ক্যাপচা — যেমন `7Gemq4`, বা অংক — যেমন `7+4`)। ক্যাপচা ছাড়া রেজাল্ট পাওয়া যায় না। তিনটা পথ আছে:

### ক) ক্যাপচা রিলে (✅ রেকমেন্ডেড)
আপনার ব্যাকএন্ড সরকারি সার্ভার থেকে **ক্যাপচা ছবি + সেশন কুকি** এনে আপনার সাইটে দেখায়। শিক্ষার্থী আপনার সাইটেই ক্যাপচাটা সলভ করে। আপনার ব্যাকএন্ড উত্তরটা + কুকিটা নিয়ে সরকারি সার্ভারে জমা দেয়।

> **এটাই এখন চলমান তৃতীয়-পক্ষ সাইটগুলোর পদ্ধতি।** যেমন `webresult.bd` নিজেই লেখে: *"If not cached, a captcha will appear in the result window."* — মানে ক্যাপচা শিক্ষার্থীর সামনেই দেখানো হয়, কিন্তু কাজটা তাদের ব্যাকএন্ড করে।

### খ) অটো-সলভ (⚠️ ঝুঁকিপূর্ণ)
GitHub-এর EDUBOARDBD-এর মতো হেডলেস Chrome দিয়ে ক্যাপচা নিজে থেকেই সলভ করা। টেকনিক্যালি সম্ভব, কিন্তু:
- সরকারি সার্ভারের HTML/ক্যাপচা বদলালেই ভেঙে যায়
- সন্দেহজনক ট্রাফিক ধরা পড়লে আপনার সার্ভারের **IP ব্লক** হতে পারে
- ক্যাপচার পুরো উদ্দেশ্যই অটোমেশন ঠেকানো — এভাবে ভাঙা নৈতিক ও শর্তগত ঝুঁকি

### গ) ক্যাপচা এড়ানো
সম্ভব নয় বললেই চলে — ক্যাপচা এই সিস্টেমের বাধ্যতামূলক অংশ।

## ৬. ঝুঁকি ও গুরুত্বপূর্ণ সাবধানতা

1. **অফিসিয়াল নয় — সেটা স্পষ্ট রাখুন**:
   সরকার ওয়েবসাইটগুলো শিক্ষার্থীদের **শুধু অফিসিয়াল চ্যানেল** (educationboardresults.gov.bd, eboardresults.com, SMS 16140/16222) ব্যবহারের পরামর্শ দেয় এবং তৃতীয়-পক্ষ সাইটকে "fake" বলে সতর্ক করে। তাই আপনার সাইটে স্পষ্ট লিখুন: *"অনানুষ্ঠানিক সুবিধা — অফিসিয়াল রেজাল্টের জন্য [সরকারি সাইটে যান]"*। সরকারি সাইট বলে ভুল হওয়ার মতো নাম/লোগো/ডিজাইন দেবেন না — এতে জাল সাইট হিসেবে ব্যবস্থা নেওয়ার ঝুঁকি আছে (ভারতে ফেক রেজাল্ট সাইট বন্ধের নজির আছে)।

2. **সার্ভার লোড / রেট-লিমিট (সবচেয়ে বড় টেকনিক্যাল ঝুঁকি)**:
   ফলাফল প্রকাশের দিন হাজার হাজার শিক্ষার্থী আপনার সাইটে ঢুকবে → আপনার ব্যাকএন্ড সরকারি সার্ভারে হাজার হাজার রিকোয়েস্ট পাঠাবে → সরকারি সার্ভার ধীরে/ব্লক হতে পারে এবং আপনার IP ব্লক হতে পারে। **সমাধান: ক্যাশিং বাধ্যতামূলক।**
   - রেজাল্ট পাবলিশ হওয়ার পর আর বদলায় না → একই (বোর্ড+পরীক্ষা+বছর+রোল+রেজি) এর রেজাল্ট **২৪–৪৮ ঘণ্টা** ক্যাশে রাখুন
   - তাই একই রোল দিয়ে দ্বিতীয় সার্চ আর সরকারি সার্ভারে যাবে না — ক্যাশ থেকে আসবে
   - নিজের সাইটে প্রতি-IP রেট-লিমিট দিন (যেমন: প্রতি ৩০ সেকেন্ডে ১টা সার্চ)

3. **প্রাইভেসি**:
   - রোল/রেজিস্ট্রেশন নম্বর **লগ বা স্টোর করবেন না** (ক্যাশে রাখলেও নাম/নম্বর ছাড়া শুধু রেজাল্ট রাখার চেষ্টা করুন)
   - পুরো সাইটে HTTPS বাধ্যতামূলক
   - একটা ছোট প্রাইভেসি পলিসি লিখুন

4. **ফ্র্যাজিলিটি**:
   সরকারি সাইট HTML/প্যারামিটার/ক্যাপচা বদলালে আপনার স্ক্র্যাপার ভেঙে যাবে। নিয়মিত (বিশেষত রেজাল্ট সিজনে) পরীক্ষা করা লাগবে — এটা একটা চলমান মেইনটেন্যান্স খরচ।

5. **রোবটস.txt ও শর্তাবলি**:
   সরকারি সাইটের `robots.txt` এবং ব্যবহারের শর্ত একবার দেখে নিন। অনুমতি না থাকলে স্ক্র্যাপিং ঝুঁকি হিসেবে ধরুন।

## ৮. বানাতে চাইলে কোন টেকনোলজি (পরবর্তী ধাপ)

- **ফ্রন্টএন্ড**: সরল HTML/JS, বা React/Next.js — রেজাল্ট ফর্ম + সুন্দর মার্কশিট কার্ড
- **ব্যাকএন্ড**: Node.js (Express) বা Python (FastAPI/Flask)
  - HTTP ক্লায়েন্ট + **কুকি জার** (সেশন ম্যানেজমেন্ট)
  - HTML পার্সার: Cheerio (Node) বা BeautifulSoup (Python)
  - ক্যাশ: Redis, অথবা সহজভাবে ফাইল/মেমরি/ডাটাবেস
  - রেট-লিমিট: নিজের সার্ভারে IP-ভিত্তিক
- **হোস্টিং**: Render, Railway, অথবা যেকোনো VPS/cPanel হোস্টিং
- **সুরক্ষা**: Cloudflare — আপনার সাইটে অটো-ট্রাফিক ও হামলা ঠেকাতে

## ৯. আপনার জন্য সিদ্ধান্ত

আপনার লক্ষ্য "শিক্ষার্থীদের জন্য কিছু করা" হলে, **সবচেয়ে নিরাপদ ও টেকসই** সমন্বয়:

1. নিজের ব্যাকএন্ড প্রক্সি সার্ভার (CORS সমাধান)
2. **ক্যাপচা রিলে** (অটো-সলভ নয়) — শিক্ষার্থী আপনার সাইটেই ক্যাপচা দেবে
3. **এগ্রেসিভ ক্যাশিং** (২৪–৪৮ ঘণ্টা) — সরকারি সার্ভারে চাপ কম, IP ব্লকের ঝুঁকি কম
4. স্পষ্ট "অনানুষ্ঠানিক" ঘোষণা + অফিসিয়াল লিংক — ফেক-সাইট ঝুঁকি এড়ানো
5. ব্যক্তিগত তথ্য সংরক্ষণ নয় + HTTPS + প্রাইভেসি পলিসি

এটা বানানো সম্পূর্ণ সম্ভব — এবং মার্কেটপ্রুফ (অনেক সাইট এভাবে চলে)। শুধু খেয়াল রাখতে হবে: **ক্যাশিং ও ক্যাপচা ম্যানেজমেন্ট** — বাকিটা সহজ ওয়েব ডেভেলপমেন্ট।
